### 0.2 本轮增量发现（全部经本轮 Grep/Read 二次复核）

**代码级新发现（v1.1 未覆盖）**：

1. **`startWebRtcPlay` 的 `.arg()` 无效调用（潜在缺陷）**：`clients/built-in-app/src/controllers/StreamingController.cpp:241` — `QString("/api/v1/zlm/webrtc/play").arg(streamId)`，路径串**不含 `%1` 占位符**，`.arg(streamId)` 返回原串（streamId 被静默丢弃）。属低危（该 POST 当前仅触发信令、无路径参数语义），但属真实缺陷，须对照后端 `RestApiHandlers.cpp` 的 WHEP 端点契约修复（补 `%1` 或移除 `.arg`）。**→ 已实施 [P0-A 2026-09-21]**：streamId 改经 body 传递（`{"stream_id": ...}`）；后端契约核实结论=该端点为占位 SDP stub（`RestApiHandlers.cpp:28074`），两端已加注释标注真实通路（`WebRtcClient.h:9` ZLM 直连 WHEP）。
2. **RBAC 按钮级控制底层为「角色名启发式」而非权限矩阵**：`clients/built-in-app/src/controllers/RbacController.cpp:134-144` — `hasPermission()` 实现为「角色名 == admin/super_admin 直通，否则 `name.contains(resource)`」，`operation` 参数 `Q_UNUSED`。`PermissionCheck.qml`（60 行，被 ModelManagementView/PipelineEditorView/DevicesView/AlarmView/LinkageRuleView 等 6+ 视图使用）底层调用即此启发式——**UI 组件完备但权限语义未兑现**。v1.1 §2.2 D10 计 90% 未点破此层。**→ 已实施 [P0-B 2026-09-21]**：hasPermission 改为 auth/me 下发 permissions（"resource:operation"）精确判定（fail-closed）；执行期发现后端 `data.permissions` 已存在（`RestApiHandlers.cpp:1354`，注册默认值 :1390 同格式），纯前端即完成，无需后端新端点；顺带修复后端 data 无顶层 username 字段导致的 `m_currentUser` 空值（改从 `user.username` 取）。
3. **30s 健康巡检细粒度路径为死代码（后端字段缺口）**：客户端阈值判断已实现（`StreamingController.cpp:130-131`：`lossRate > 0.3 || failCount >= 3 || rttMs > 3000`，与任务书口径一致），但后端 `box-sdk/src/service/MediaRouter.cpp:266-283` `getHealthJson()` **仅返回 `{zlm_status, timestamp}`**——客户端 `streams[]` 细粒度分支（`StreamingController.cpp:119-147`）永不触发，实际走 `zlm_status` 粗粒度降级路径（`StreamingController.cpp:110-112` 诚实注释已自知）。v1.1 §6.2 巡检行标「缺口：—」，本轮实证该缺口存在。**→ 已实施 [P0-C 2026-09-21]**：getHealthJson 扩展 `streams[]`（channelId/streamId/active/lossRate/failCount/rttMs）；lossRate 取自 ZLM getMediaList `loss` 字段（`ZLMMediaSource` 新增 loss 解析，`ZLMMediaKitAdapter.cpp:2149+`）；failCount/rttMs 固定 0/-1 如实注释（客户端阈值语义 -1 永不触发）；真机 iptables 注入验证待窗口。
4. **水印为「半闭环」并在 UI 内诚实标注**：`clients/built-in-app/src/views/RecordingView.qml:1289-1299` 脚注明示——水印由 AI 分析管线 OSD 插件（WatermarkAnnotator）对视频帧叠加，`channel_watermarks` 表**当前仅保存/回显闭环，与渲染管线无自动桥接**，颜色字段已保存待渲染升级生效。与 v1.1 §2.4-5 结论一致，本轮补充了 UI 内脚注这一事实（用户可见的诚实声明，非隐藏缺陷）。

### 2.3 矩阵读法与交叉结论（承 v1.1 §3.5，本轮补强）

1. **端侧直接可比面（海康/大华/华为/Axis 的规则+联动列）我方已无能力空白**：58 类动作/条件树/AXIS 时序/dry-run 后端齐备且两端接线（P1-2/P2-3 于 09-20 真机闭合）——剩余是「好用性打磨」而非「能力补齐」。
2. **明确落后的三项维持诚实标注**（不因端侧定位取消）：视频语义检索（→ Web/云承接，`RetrievalView.vue` 已是承接载体）、视频摘要浓缩（BriefCam）、自学习分析（Avigilon）。
3. **差距最大的两格是「生态规模」而非「功能」**：极视角算法 1500+、Milestone 驱动 9000+——端侧单机形态不以其为考核标准（v1.1 §3.5-6），但对外宣传口径必须如实（§4.5）。
4. **我方差异化集中在 ⑥ APP 端独有交互**（§1.4 七项）+ **轻量全私有化不绑定厂商生态**——这也是 §2.2 中 Axis/海康 ⑥ 列「差异化」评级的依据。
